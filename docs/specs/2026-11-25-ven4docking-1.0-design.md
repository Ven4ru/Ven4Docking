# Ven4Docking 1.0.0 — спецификация

Дата: 25.11.2026. Статус: дизайн согласован владельцем по частям (макет редактора — личный артефакт владельца).
Исходный прототип — Python-агент + страница + лаунчер (вне репозитория), работает на realme C11 с 25.11.2026.

## 1. Что это

Ven4Docking превращает старый Android-телефон в настенную тач-панель домашнего ПК: часы, погода, нагрузка ПК,
серверы, лимиты нейросетей, запуск приложений, медиакнопки. Публичный проект `Ven4ru/Ven4Docking`, лицензия MIT,
стиль и тема — как у клиента Ven4Tools, часть семейства Ven4verse. Иконка — Венчик с телефоном в лапах.

Цели 1.0:
- любой пользователь Windows 10/11 ставит программу установщиком и за 5 минут получает работающую панель на телефоне с Android 7+;
- экраны, блоки и список приложений настраиваются в редакторе без правки файлов;
- агент почти не грузит ПК;
- в репозитории нет секретов и личных данных.

Не входит в 1.0: версия мастера для Linux (следующая неделя), один телефон на несколько ПК, уведомления на панель,
Home Assistant, iPhone.

## 2. Архитектура

```
 ┌──────────── ПК (Windows) ─────────────┐            ┌──── Телефон (Android 7+) ────┐
 │ ven4docking-agent.exe (Rust, фон, трей)│◄── LAN ───►│ лаунчер ru.ven4tools.docking  │
 │  • метрики ПК, медиа, запуск программ  │  HTTP+токен│  WebView ← панель (HTML/JS)   │
 │  • SSH к серверам (внутри процесса)    │  UDP-поиск │  мост DockAndroid (яркость,   │
 │  • лимиты нейросетей (только файлы)    │            │  батарея, привязка, версия)   │
 │  • раздаёт панель и раскладку          │            └───────────────────────────────┘
 │        ▲ localhost-API + ключ          │
 │ Ven4Docking.exe (WPF .NET 10, редактор)│── adb (USB / Wi-Fi-отладка) ──► телефон
 └────────────────────────────────────────┘
```

Три части, у каждой одна задача:
1. **Агент** (`agent/`, Rust) — всё, что должно работать постоянно. Без окон, иконка в трее (меню: «Открыть редактор», «Пауза», «Выход»).
2. **Редактор** (`editor/`, WPF .NET 10) — всё, что нужно редко: настройка, мастер телефона, обновления. Закрывается полностью.
3. **Телефон**: лаунчер (`android/`) + панель (`panel/`), которую раздаёт агент.

Данные пользователя — `%APPDATA%\Ven4Docking\`: `config.json`, `layouts\<phone-id>.json`, `icons\`, `admin.key`, `agent.log`.
Программы — `%LOCALAPPDATA%\Programs\Ven4Docking\`.

## 3. Агент (Rust)

### 3.1 Состав
- HTTP: `axum` + `tokio`, слушает `0.0.0.0:8765` (порт в конфиге).
- Метрики: `windows` (windows-rs) — PDH (GPU Engine, GPU Adapter Memory, Thermal Zone), D3DKMT (имя/температура/вентилятор GPU), WinRT `GlobalSystemMediaTransportControlsSessionManager` (что играет), `keybd_event` (медиаклавиши), `ShellExecuteW` (запуск); `sysinfo` — ЦП по ядрам, частота, память, диски, сеть, процессы.
- SSH: `russh` + `russh-keys`. Ключ — системный (`%USERPROFILE%\.ssh\id_ed25519`, `id_rsa`), проверка хоста по `%USERPROFILE%\.ssh\known_hosts` (неизвестный или изменившийся ключ хоста — ошибка, не принимать молча). Одна сессия на сервер, удалённая команда печатает `/proc/stat`, `/proc/loadavg`, `/proc/uptime`, `/proc/meminfo`, `df -P /` раз в N секунд (как в прототипе, класс `ServerWatch`). Пинг — ICMP через `IcmpSendEcho` (iphlpapi), запасной — время TCP-подключения к порту SSH.
- Трей: `tray-icon`. Автозапуск — `HKCU\...\Run`.
- Логи: `tracing`, файл с ротацией 1 МБ × 3.

### 3.2 Умный опрос (бюджет нагрузки)
Цель: ≤ 15 МБ памяти, ≤ 0,3 % всего процессора в среднем при одной активной панели (прототип на Python: 35 МБ, 1,1 %, плюс 85 МБ на 7 ssh.exe).
- Панель «активна», пока её телефон запрашивал состояние за последние 10 с. Нет активных панелей — опрос ЦП/GPU/сети раз в 10 с, процессы и медиа не опрашиваются, SSH-сессии держатся.
- Опрашивается только то, что есть в раскладках подключённых телефонов (нет блока «Видеокарта» — нет PDH GPU).
- Процессы — раз в 5 с, медиа — раз в 2 с, файлы нейросетей — по изменению времени файла, не чаще раза в 5 с.
- Счётчики PDH открываются один раз; GPU Engine — самый дорогой, раз в 2 с.

### 3.3 HTTP API для телефона (из локальной сети)
Доступ: адрес клиента из частных сетей (10/8, 172.16/12, 192.168/16, 100.64/10, 127/8); иначе 403. Брандмауэр — правило «Ven4Docking» TCP 8765 + UDP 8766, `RemoteAddress LocalSubnet`.
Авторизация: заголовок `Authorization: Bearer <токен телефона>`; статика панели и `/pair/*` — без токена.
- `GET /` и статика панели.
- `GET /api/v1/layout` → раскладка этого телефона (по токену) + `version`.
- `GET /api/v1/state?blocks=cpu,gpu,...` → данные только для нужных блоков.
- `POST /api/v1/launch {app}` — только `app` из списка в конфиге.
- `POST /api/v1/media {action}` — `playpause|next|prev|stop|volup|voldown|mute`.
- `POST /api/v1/phone {battery, temp, charging, webview, android, model, launcherVersion}` — телефон сообщает о себе раз в минуту.
- `POST /api/v1/hello {nonce}` — без токена: `{"proofs":[…]}`, для каждого привязанного телефона HMAC-SHA256(ключ — его `tokenHash` как хранится, сообщение — `nonce`); `nonce` — 32–128 шестнадцатеричных знаков, иначе 400; больше 10 запросов в секунду с адреса — 429. Нужен лаунчеру, чтобы найти свой ПК после смены адреса (раздел 7).
- `POST /pair/start {model, android, deviceId}` → `{pairId, code}` (4 цифры, живёт 2 мин, не больше 5 попыток в минуту с адреса); `GET /pair/{pairId}` → `{status: wait|ok|denied, token?}`.

### 3.4 Поиск ПК
UDP 8766, широковещательный запрос `V4D?1` → ответ `{"name":"<имя ПК>","port":8765,"ver":"1.0.0"}`. Агент отвечает только на запросы из частных сетей.

### 3.5 API редактора (только localhost)
`127.0.0.1:8765/admin/*`, заголовок `X-Admin-Key` = содержимое `admin.key` (32 байта случайных, файл доступен только пользователю).
Методы: `GET/PUT /admin/config`, `GET/PUT /admin/layouts/{phone}`, `GET /admin/phones`, `POST /admin/phones/{id}/revoke`, `GET /admin/pairs`, `POST /admin/pairs/{id}/accept|deny`, `POST /admin/servers/test {server}`, `GET /admin/ai/sources`, `GET /admin/status` (версия, нагрузка, ошибки блоков), `POST /admin/reload`.
Сохранение раскладки увеличивает `version`; панель видит новую версию при следующем опросе и перестраивается без перезагрузки.

## 4. Конфиг и раскладка

`config.json` (пример, все поля необязательные кроме `version`):
```json
{
  "version": 1,
  "port": 8765,
  "theme": "teal",
  "language": "ru",
  "weather": {"name": "Москва", "lat": 55.75, "lon": 37.62},
  "apps": [{"id": "telegram", "title": "Telegram", "kind": "shortcut|exe|url|command", "target": "...", "args": "", "icon": "icons/telegram.png"}],
  "servers": [{"id": "site", "name": "Сайт", "host": "203.0.113.10", "port": 22, "user": "root", "key": "auto"}],
  "ai": {"enabled": ["claude-code", "claude-desktop", "codex", "ollama", "lmstudio"]},
  "phones": [{"id": "p1", "name": "realme C11", "tokenHash": "...", "night": {"from": "23:00", "to": "07:00", "brightness": 0.02}, "dimWhenPcOffline": true, "burnInShift": true}]
}
```
Токены хранятся только хешем (SHA-256). Сам токен знает телефон.

`layouts/<phone>.json`:
```json
{"version": 7, "orientation": "landscape", "grid": {"cols": 8, "rows": 4},
 "screens": [{"id": "s1", "name": "Главный", "blocks": [
   {"id": "b1", "type": "clock", "x": 0, "y": 0, "w": 3, "h": 2, "opts": {"weather": true}},
   {"id": "b2", "type": "apps", "x": 0, "y": 3, "w": 5, "h": 1, "opts": {"apps": ["telegram","chrome"]}}]},
  {"id": "s2", "name": "Серверы", "blocks": [
   {"id": "b3", "type": "servers", "x": 0, "y": 0, "w": 8, "h": 4, "opts": {"servers": ["site"]}}]}]}
```
Правила: блоки не пересекаются и не выходят за сетку (проверяет и редактор, и агент при сохранении); экранов 1–10; любой тип блока необязателен и может повторяться.

## 5. Блоки 1.0

| Тип | Показывает | Источник | Настройки |
|---|---|---|---|
| `clock` | время, дата, погода (по желанию) | часы телефона; open-meteo с телефона | погода вкл/выкл, 12/24 ч |
| `weather` | погода отдельно | open-meteo | — |
| `cpu` | загрузка, ядра, частота, температура | sysinfo, PDH Thermal; LibreHardwareMonitor если есть | ядра, пороги |
| `gpu` | загрузка, температура, VRAM, вентилятор, график | PDH, D3DKMT | какая видеокарта, что показывать, пороги |
| `ram` | память, аптайм | sysinfo | пороги |
| `disks` | заполненность дисков | sysinfo | какие диски |
| `net` | скорость, график, самый загруженный процесс | sysinfo | адаптер |
| `ai` | лимиты нейросетей + «данные от …» | только файлы (раздел 6) | какие источники |
| `apps` | значки приложений, любой размер вплоть до экрана | список приложений | набор и порядок |
| `media` | что играет, кнопки | WinRT, медиаклавиши | какие кнопки |
| `servers` | пинг, ЦП, ОЗУ, диск, LA, аптайм по серверам | SSH внутри агента | какие серверы, пороги |
| `phone` | заряд, температура батареи, зарядка | мост DockAndroid | порог перегрева |

Шаблоны первого запуска: «Классика» (как прототип), «Монитор ПК», «Только приложения».
Ночь и яркость, сдвиг против выгорания — настройки телефона (раздел 4), не блоков.

## 6. Нейросети — только без риска бана

Правило владельца: если НАШ способ брать лимиты может привести к блокировке аккаунта — модуль не делаем. Исследование: `docs/research/ai-limits.md` (локально, в репозиторий не входит: описывает рабочее место автора; публичная выжимка — позже).
- Разрешено только чтение файлов, которые официальные программы сами пишут на диск, и локальные API без аккаунта:
  - Claude Code — JSON строки состояния (`rate_limits`); Ven4Docking не ставит свой скрипт строки состояния без явного согласия пользователя в редакторе;
  - Claude Desktop — `%APPDATA%\Claude\plan-usage-history.json` (нерегулярно, без времени сброса);
  - Codex — события `token_count.rate_limits` в `~/.codex/sessions/**/rollout-*.jsonl`;
  - Ollama (`127.0.0.1:11434/api/ps`), LM Studio (локальный сервер) — загруженная модель.
- Запрещено в коде совсем (не «выключено», а нет кода): чтение `.credentials.json`/`auth.json`/`oauth_creds.json`, любые токены и cookie, закрытые эндпоинты (`/api/oauth/usage`, `copilot_internal`, `retrieveUserQuota` и т. п.). Тест в CI ищет эти строки в исходниках агента.
- Каждый источник показывает время замера; полоска скрыта, если замер старше окна или после него был сброс (логика прототипа `read_claude_limits`).
- Остальные (ChatGPT Desktop, Gemini, Antigravity, Cursor, Copilot) — только «установлено, лимиты недоступны».

## 7. Лаунчер (Android)

- Пакет `ru.ven4tools.docking`, `minSdk 24` (Android 7.0), `targetSdk 34`, Gradle, Java. Подпись в CI ключом из секретов; локальная тестовая сборка — debug-ключом.
- База — `MainActivity` прототипа: HOME-активность, WebView на весь экран, повтор при ошибке, пересоздание WebView после падения, скрытое меню (5 касаний в левый верхний угол).
- Новое:
  - экран привязки: поиск ПК по UDP, список найденных, ввод адреса вручную, показ 4-значного кода, ожидание подтверждения; токен хранится в `SharedPreferences` (`MODE_PRIVATE`), в адрес не попадает;
  - мост `DockAndroid`: `setBrightness`, `version`, `battery()` (уровень, температура, зарядка), `info()` (модель, Android, WebView);
  - повторный поиск ПК: если сохранённый адрес не отвечает 30 с подряд (страница не грузится или панель сообщила через мост `DockAndroid.offline(true)`), лаунчер ищет агенты по UDP не чаще раза в 60 с и каждому новому адресу шлёт `POST /api/v1/hello` со свежим `nonce`; адрес принимается, только если в `proofs` есть HMAC-SHA256(sha256hex(токен), nonce). Токен непроверенному адресу не отправляется; повторы раз в 5 с идут как раньше;
  - проверка обновления: агент отдаёт `/apk/latest.json`; при новой версии — плашка «Есть обновление», по нажатию — установка через `PackageInstaller`;
  - Android 7–8: `RUN_IN_BACKGROUND` вместо `RUN_ANY_IN_BACKGROUND`, без `locksettings` на 7.

## 8. Панель (страница)

- Исходники `panel/src` (JS-модули + CSS), сборка `esbuild` в один `index.html` + `app.js`; цель — Chrome 51 (WebView Android 7 без обновлений): `--target=chrome51`.
- CSS без `inset`, без `gap` у flex, без `aspect-ratio`, без `:is/:where`, без `clamp()` — проверяет `stylelint-no-unsupported-browser-features` с browserslist `Chrome >= 51`; JS — `eslint-plugin-compat`.
- Раскладка строится по `layout.json`: CSS Grid (Chrome 57+) с запасным вариантом на абсолютном позиционировании по клеткам для Chrome 51–56.
- Каждый блок — модуль с `render(el, opts)` и `update(data)`; блок, не получивший данные, показывает свою ошибку, остальные работают.
- Перенести из прототипа: свайп между экранами, точки, ночное приглушение, сдвиг против выгорания, «ПК не отвечает».

## 9. Редактор (WPF .NET 10)

- Вид — по согласованному макету: полоска разделов слева, тёмная тема, акцент по теме Ven4Tools (палитры «Бирюзовая», «Зелёная», «Светлая» из `Ven4Tools/Services/ThemeService.cs`, тот же автор, MIT). MVVM (`CommunityToolkit.Mvvm`), локализация RU/EN (`.resx`).
- Разделы:
  - **Телефоны** — список, карточка телефона (модель, Android, WebView, заряд, связь, «Отозвать», ночь/яркость), мастер подключения, запросы привязки «Подключить realme C11? Код 4821». На первом шаге мастера и в карточке — пояснение «По кабелю надёжнее» (ПК всегда может обновить лаунчер и вернуть настройки; Wi-Fi-отладка выключается после перезагрузки или смены сети; без отладки настройки делаются вручную).
  - **Экраны** — список экранов, палитра блоков, предпросмотр (WebView2 показывает настоящую панель в разрешении телефона, данные живые или примерные), сетка 8×4, перетаскивание и изменение размера, настройки блока справа, «Сохранить».
  - **Приложения** — из меню «Пуск», exe, ссылка, команда с параметрами; иконки извлекаются автоматически; порядок перетаскиванием.
  - **Серверы** — добавление, «Проверить подключение» (ошибки понятными словами: таймаут, порт закрыт, ключ не принят, ключ хоста не совпал).
  - **Нейросети** — найденные источники, время последних данных, вкл/выкл.
  - **Настройки** — тема, язык, погода (поиск города через open-meteo geocoding), автозапуск агента, порт.
  - **О программе** — Венчик, версия, «Проверить обновления», ссылка «Семейство Ven4verse» (ven4tools.ru).
- adb: редактор скачивает Android platform-tools с `dl.google.com` при первом запуске мастера, с согласия пользователя (лицензия Google не даёт класть adb в наш установщик), в `%LOCALAPPDATA%\Ven4Docking\platform-tools`.
- Мастер:
  1. способ: USB (Android 7+) или Wi-Fi-отладка (Android 11+, `adb pair` по коду);
  2. определение марки и версии → инструкция из `docs/research/phone-brands.md` (данные — в `editor/Assets/brands.json`; непроверенные пункты помечены «может называться иначе»);
  3. установка APK и настройка (рабочий стол, экран не гаснет на зарядке, таймаут 30 мин, без блокировки, фон, часовой пояс как у ПК, анимации 0,5), команды под версию Android, проверка результата каждой; если `settings`/`appops` запрещены (realme/OPPO) — подсказка про «Отключить контроль разрешений» и повтор;
  4. передача адреса и токена (привязка без кода — редактор сам создаёт токен);
  5. проверка WebView (версия ниже 57 — предупреждение «панель упрощённая»);
  6. совет про ограничение заряда для этой марки;
  7. готово + «Ven4Docking — часть семейства Ven4verse» (ссылка на ven4tools.ru).
- Обновления: при запуске редактора — GitHub Releases `Ven4ru/Ven4Docking`; установка только по кнопке.

## 10. Безопасность и приватность

- Никакой телеметрии. Сеть наружу: open-meteo (погода, с телефона и для поиска города), GitHub Releases (проверка обновлений), dl.google.com (platform-tools, по согласию), SSH к серверам пользователя.
- Запуск только приложений из списка; команда — только та, что пользователь сам записал в список.
- Токены телефонов — хешем; `admin.key` — только для пользователя; API редактора — только с 127.0.0.1.
- Репозиторий: ключ подписи APK, пароли, `config.json`, серверы, журналы — не попадают (`.gitignore` + проверка `commit-checker` перед коммитом). В примерах — адреса из документационных диапазонов (203.0.113.0/24).

## 11. Ошибки

- ПК недоступен → панель: «ПК не отвечает», повтор каждые 5 с, приглушение.
- Блок без данных → текст причины в блоке, остальные работают.
- Агент не запущен → редактор: «Агент не запущен — запустить?».
- Телефон перегрелся (по умолчанию ≥ 45 °C) → блок «Телефон» красный, в трее уведомление (вкл/выкл).
- Сохранение раскладки с пересечением блоков → редактор не даёт сохранить и подсвечивает.

## 12. Проверки

- Агент: `cargo test` — разбор `/proc`, файлов нейросетей (на образцах из `agent/tests/fixtures`), конфига и раскладки, проверка запрещённых строк (раздел 6).
- Панель: `npm run lint` (совместимость с Chrome 51), сборка.
- Редактор: юнит-тесты моделей (раскладка, пересечения, конфиг).
- Ручной прогон тестового образца (по команде владельца):
  - Windows: чистая ВМ Windows 11 и Windows 10 (по одной ВМ за раз) — установка, автозапуск, редактор, правило брандмауэра, нагрузка агента;
  - Android: эмулятор Android 7.0 (API 24) и Android 10 (API 29), образы скачиваются с согласия; мастер по adb, привязка по коду, панель, свайп, обновление лаунчера;
  - живой realme C11 — переход с прототипа (`ru.dockpanel.kiosk` удаляется, ставится `ru.ven4tools.docking`).

## 13. Сборка и выпуск

- GitHub Actions: push → сборка агента (`cargo build --release`, x86_64-pc-windows-msvc), панели, редактора (`dotnet publish` self-contained), APK (Gradle), проверки, артефакт. Метка `vX.Y.Z` → установщик NSIS, zip, `SHA256SUMS`, выпуск на GitHub. Выпуски собираются только в Actions.
- Установщик: на пользователя, без прав администратора; правило брандмауэра — отдельным шагом с запросом прав (если отказали — агент работает, но телефон не достучится; редактор показывает это).
- Выпуск 1.0.0 и публикация репозитория — только по слову владельца.

## 14. Иконка

Венчик с телефоном в лапах на основе талисмана Венчика (исходники талисмана — вне репозитория); генерация изображения — по согласию владельца на траты; из одной картинки — `ico` редактора/агента, значок лаунчера (адаптивный), картинка «О программе», README.

## 15. Порядок работ (тестовый образец)

1. Агент на Rust с возможностями прототипа + умный опрос + SSH внутри + API v1.
2. Панель по раскладке, сборка под Chrome 51.
3. Лаунчер: новый пакет, привязка, мост батареи, обновление.
4. Редактор: разделы, предпросмотр, сохранение.
5. Мастер и `brands.json`.
6. Нейросети и блок «Телефон».
7. Установщик и Actions.
8. Иконка.
9. Прогон на ВМ Windows и эмуляторах Android, затем realme C11.

«Тестовый образец» = всё из 1–9 работает и проверено; репозиторий локальный (не опубликован), выпуска нет.
